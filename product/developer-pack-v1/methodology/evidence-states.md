# Evidence States

Prompt Quarry keeps prompt quality claims proportional to observed evidence.

## DRAFT

The artifact exists, but static acceptance has not been established.

## VALID

Static contracts pass: structure, required variables, consistency, output contract, provenance, and claim boundaries are acceptable.

`VALID` does not mean the prompt was behaviorally tested.

## TESTED

Requires real F4 runtime observations under the defined evaluation protocol.

## CANDIDATE / IMPROVED

Requires F5 evidence that a candidate performs better than the relevant baseline under comparable conditions.

## CERTIFIED

Requires F6 repeated evidence against the same target/runtime scope.

## PORTABLE

Requires F7 evidence across providers or materially different runtime targets.

## Claim discipline

Always use the strongest state actually supported, never the state you expect an artifact to reach later.

Commercial release status is separate from prompt maturity. A product can be packaged successfully while its included prompt assets remain `VALID`.
