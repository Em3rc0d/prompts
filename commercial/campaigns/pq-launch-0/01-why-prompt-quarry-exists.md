## LinkedIn draft

I don't think developers need another folder with 1,000 AI prompts.

The problem usually isn't that we have too few prompts.

It's that when the work starts to matter, the prompt often doesn't say enough about the work itself:

- What context can change the answer?
- What constraints are non-negotiable?
- What evidence is actually available?
- What should the output look like?
- What should the model do when the evidence isn't enough?

That is the idea behind **Prompt Quarry**.

I'm treating prompts less like clever sentences and more like engineering artifacts: something you can structure, inspect, adapt, version, and govern.

The operating principle is simple:

**AI proposes. Human decides. System executes. System proves.**

And there is another rule I care about just as much:

**not observed == unknown**

If something has only passed a static quality check, I don't want to market it as battle-tested or universally proven. The label should describe the evidence we actually have.

I'm starting small with a free **Developer Starter Pack v1**: three structured prompts for Code Review, Bug Diagnosis, and Technical Decisions.

No giant prompt dump. No magic-prompt promise.

Just three artifacts you can try on real developer work before deciding whether the larger system is useful to you.
